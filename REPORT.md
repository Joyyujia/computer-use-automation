# Architecture

The system is a single TypeScript process with explicit boundaries for orchestration, model decisions, surface control, policy, evidence, replay, and handoff. A run orchestrator owns the browser session rather than either discovery or replay; this makes pausing and transferring the exact same session possible. Playwright is the first surface adapter because it gives a real application surface and observable accessibility semantics, while the artifact remains independent of Playwright types.

Discovery first opens and policy-checks the configured target, then enters a bounded observe -> decide -> policy-check -> act loop. It enforces a step cap, overall deadline, model-call deadline, and repeated-state/action detection. The OpenAI adapter requests one strict JSON-schema object envelope per iteration, disables response storage, and records provider response IDs; the envelope is converted into a locally discriminated decision only after validation. A scripted adapter exists only for repeatable tests and cannot mark provenance live. Replay is a separate code path with no model dependency. The single-process choice keeps this vertical slice inspectable; the session registry and evidence interfaces are seams for durable services later.

# Artifact schema

A capability is an agent-callable contract, not a raw transcript. It declares a schema version, semantic version, stable ID, typed inputs and outputs, app-family compatibility, ordered typed steps, locator rationales and fallbacks, risk levels, timeouts, retries, business-outcome detectors, bounded recovery rules, a final checkpoint, approval state, and discovery provenance.

The artifact compiler converts only successfully executed discovery decisions into parameter references. Runtime member data is represented as `{ source: "input", key: "memberId" }`, never embedded as a discovered literal. Fallback locators must declare the same `logicalTarget`; ambiguous primaries fail immediately, while missing or hidden controls wait under the step deadline and a hidden primary never falls through to a fallback. Runtime-text extraction locators are rejected. Before persistence, the exact generated artifact is replayed in a fresh browser with the same invocation and its typed outputs must match discovery. Artifacts start as `draft`; replay accepts drafts for assignment demonstration, so approval is metadata here. A production registry must enforce `approved` before dispatch.

The learned portion is deliberately narrow: ordered navigation, fill, click, and extraction targets. The reviewed `lookupBalanceProfile` supplies the identity-equality checkpoint, detail visibility requirement, output type, `member_not_found` detector, bounded service-notice recovery, and session-expiry intervention. These additions are listed in provenance. A model-proposed generic heading cannot weaken the reviewed success contract, and a model-proposed business outcome is returned only when both its assertion and the same-code reviewed detector match live application state.

# Determinism & error handling

Replay validates the complete artifact and required inputs before launching a browser. After submission it waits under one deadline for competing configured states: business outcome, intervention, recovery, or identity-matched success. It clears and rejects stale fixture state, verifies the displayed member ID equals the invocation, validates every declared output, and checks no contradictory outcome remains. Every execution attempt, including an automatic retry, revalidates current page and frame origins immediately before acting. Clicks and navigation are not blindly retried after uncertain effects; fill, select, extract, and assert retries remain bounded by the artifact.

The public result distinguishes `success`, `business_outcome`, `intervention_required`, and `failure`. Failure categories include policy denial, timeout, missing or ambiguous target, invalid output, checkpoint failure, unexpected dialog/state, expired session, and control conflict. Failures include run and step IDs, expected state where applicable, a sanitized observed-state summary, and an evidence path. “Member not found” is a stable business outcome rather than a technical exception.

# Heterogeneity & multi-tenant

The `PlaywrightSurface` implements observation, targeting, action, extraction, and assertion behind a surface boundary. Observations report actual semantic roles and associated labels; a bare HTML `name` is not represented as a label. App-declared extraction fields expose a stable executable locator and semantic name while their values remain redacted. For legacy pages without those attributes, visible table cells, definition values, and output elements become candidates only when they have a stable ID plus a nearby label; anything weaker is escalated rather than guessed. Named frame paths are observed and can be replayed. Roles and labels are preferred, then scoped CSS; coordinates are treated as risky and require approval. Action resolution polls for delayed controls only until the step deadline.

Artifacts are keyed by vendor app family rather than tenant. A production registry would attach supported version ranges and allow narrow tenant overlays for entrypoints, labels, and locator mappings while forbidding silent changes to behavior or risk. Failure telemetry should quarantine a failing tenant/version range and route it for review instead of launching open-ended recovery.

# Escalation & handoff

Automation and the operator share a retained Playwright browser context. An intervention contains run, session, capability/goal, step, reason, sanitized context, evidence, state, owner, and human action history. The operator explicitly takes a single-owner control lease; the execution boundary rejects automation while the human owns it. The local console polls live screenshots, forwards coordinate clicks and keyboard input to the same page, records redacted action descriptions, and supports resume or abort. On resume, replay verifies the configured blocking condition has cleared before continuing.

Unexpected execution, recovery, terminal-wait, checkpoint, and output-validation failures also enter this same handoff path when an operator is configured. Safe actions such as fill/extract receive at most one bounded retry after the operator repairs the state. Click and navigation failures are not blindly repeated after an uncertain effect; the operator-completed state must satisfy the capability checkpoint, business outcome, requested navigation URL, or cleared recovery trigger. Final outputs may be re-extracted once after intervention and are then revalidated. This is a minimal but real handoff in the retained browser session rather than a simulated second session. Production additions would include authentication, encrypted transport, durable intervention state, streaming video, operator identity, lease expiry, and stronger keyboard/input controls.

# Safety

Discovery, replay, recovery, and resumed actions pass through the same configurable policy. Replay authorizes the pending main step before detector checks, recovery, handoff, or any other pre-step side effect. Recovery actions and post-intervention output refreshes are separately authorized. In addition, the execution boundary validates browser state before every attempt, so a failed attempt that changes origin cannot act again under stale authorization. The policy restricts origins, routes, and actions; validates resolved input-sourced navigation URLs; checks post-action redirects; closes and rejects unexpected popups; and safely classifies browser dialogs. Trusted target patterns inspect the full fallback tree, and coordinate use can require approval even when a model or artifact says `safe`. Unknown actions and origins fail closed.

Sensitive fields are parameterized. DOM observation walks rendered text only, removes script/style content, masks declared and legacy extraction regions and input values, and sanitizes URL state. The complete model context, including target URL and prior model decisions, passes through the same value-aware redactor used for every evidence write. It covers declared runtime values, URL credentials/query/fragment values, and common email, SSN, and currency patterns. Extraction values marked sensitive are returned to the caller but not logged. Generated artifacts reject URL state, known runtime literals, and any text the persistence redactor would alter. Failure evidence is sanitized JSON, while operator screenshots are live and not persisted. These controls are defense in depth, not universal PII discovery.

# Cuts

The implementation intentionally omits production authentication, durable databases/queues, desktop automation, durable tenant overlays, an enforced artifact-approval registry, and unbounded LLM recovery. The operator console is local and deliberately minimal. Frame fallback for unnamed, unstable layouts is limited, and no pattern-based redactor can guarantee universal PII detection. Only fictional demo data should be used.

The repository keeps scripted mechanics fixtures explicitly labeled non-live and a separate reviewed submission bundle under `evidence/submission/`. The latter contains a genuine API-backed discovery with provider response IDs and live provenance, the exact generated artifact and checksum, model-disabled replay for a distinct valid member, an explicit not-found outcome, a delayed success, and a same-session human handoff with a recorded preview click. It also retains a separately indexed post-hardening API-backed discovery and model-disabled exact-artifact replay as supplemental independent verification. The remaining cuts are production hardening rather than assignment blockers: stronger operator authentication, durable state, broader legacy extraction support, an enforced approval registry, and richer evidence attestation beyond the reviewed index and artifact digest.
